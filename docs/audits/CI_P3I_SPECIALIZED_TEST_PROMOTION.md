# CI-P3I — Specialized canonical domain-test promotion

Issue #467.

## Decision

SV Evidence and IO Testing remain distinct review checks, but pull requests no
longer compile and test the same ARSAS application a second time on Windows.
They consume the exact canonical Build ARSAS regression artifact instead.

## Exact authority

The shared canonical verifier continues to require:

- exact PR head and branch;
- exact synthetic merge/source SHA;
- exact ARIEC61850 integration SHA;
- latest matching Build ARSAS run ID and attempt;
- safe, bounded, non-expired ARSAS-test-evidence artifact;
- exact canonical manifest and TRX SHA-256;
- globally all-pass TRX counters.

P3I adds an optional required-test-family proof. Every requested substring must
match at least one UnitTestResult with outcome Passed. A missing family or any
matching non-Passed result fails closed.

SV requires SmvSnapshotEvidenceExporterTests.

IO requires IoTest, IoList, IoFat, FatDataSet and FatScl.

The production main TRX at the P3I start point contained 6 SV evidence tests
and, respectively, 110 / 12 / 169 / 2 / 12 matching IO-family results.

## Runner routing

For pull_request, both existing workflow/job check names are preserved but the
job runs on ubuntu-latest and only performs exact identity + canonical TRX
verification. No .NET restore/build/test is executed in those PR lanes.

For workflow_dispatch, the same workflows continue to run on windows-latest
and retain the focused restore/build/filter-test diagnostic path.

## Artifact contract

The existing ARSAS-sv-evidence-test-results and
ARSAS-io-testing-test-results artifact names remain stable on PRs. Their PR
payload is now an inspectable canonical domain-proof JSON rather than a second
TRX generated by duplicate execution. Manual diagnostics continue to publish
their focused TRX files.

## Static topology

No workflow file, checkout action, setup-python action, setup-dotnet action,
upload-artifact action, or static dotnet restore/build/test count is added.
Manual fallback commands stay in YAML intentionally, so P0 static limits do
not change even though PR execution no longer allocates a Windows runner.

## Authority boundary

This milestone changes only specialized PR verification execution. It does not
change canonical Build ARSAS, Windows package authority, installer authority,
release promotion, R10/P141 physical evidence, or IEC 61850 runtime behavior.

## Rollback

Restore pull_request execution to the focused Windows restore/build/test path.
Never remove exact canonical identity or required-domain-test checks merely to
make the specialized workflow green.
