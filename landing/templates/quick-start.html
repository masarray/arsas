Install · connect · discover · observe · preserve

Move from a verified package to live IEC 61850 evidence you can reuse.

This onboarding path is intentionally read-first. Complete the first attributable value before continuing into reporting, files, GOOSE, control or IP-to-SCL generation. Teams starting from an approved test sheet can use the separate IO List FAT path.

1

Verify and prepare the Windows package

Choose Installer or Portable ZIP, compare the downloaded file with the published SHA-256, then review the honest Authenticode status. SmartScreen may identify the current public build as an unrecognized publisher because it is unsigned.

Verify package
2

Confirm the approved network path

Connect the engineering laptop only to the approved laboratory, FAT, SAT or commissioning network. Confirm addressing, routing and TCP port 102 before changing application settings. Npcap is needed for raw-Ethernet GOOSE or Sampled Values capture, not for ordinary MMS client reads.

Port 102 diagnostics
3

Add the IED endpoint

Enter the approved IPv4 address and keep the default IEC 61850 MMS port unless the project procedure explicitly defines another endpoint. A successful TCP connection is not yet proof of a complete MMS association or service support.

4

Discover the complete live MMS model

Allow ARSAS to read the physical server identity, Logical Devices, Logical Nodes, Data Objects, Data Attributes, DataSets, Report Control Blocks and available type information. Treat the online model as current server evidence and SCL as configured intent.

MMS Client workflowLive model vs SCL
5

Select one signal and inspect its evidence

Choose a known read-only attribute and add it to Live Values. Confirm the IED source, object reference, value, quality, timestamp and acquisition source together. Do not treat a number alone as proof that the signal is valid or timely.

6

Identify reporting or polling

ARSAS can evaluate existing BRCBs and URCBs, exact DataSet coverage and visible fallback. An occupied RCB, rejected write or incomplete DataSet should remain visible rather than being converted into a false success.

Smart ReportingReporting is silent
7

Retain diagnostics and stop at the authority boundary

Save or copy the attributable diagnostics needed for the test record. Do not reserve an RCB, create a DataSet, write configuration or operate a control object unless the approved procedure, plant authority and independent safety checks explicitly permit it.

Alternative first-run path

Start from an approved IO List instead of a manually selected signal set.

The current mainline provides a dedicated SDI FAT workspace. The latest stable public installer may remain an earlier version, so review release scope before field use.

A

Choose FAT / IO List Testing

Open the ARSAS workbook for a new project or open an existing portable .arsas project.

B

Review import and live binding

Confirm project identity, IED, TestPointId, expected states and IEC 61850 object references before starting.

C

Prove OFF → ON → OFF

Obtain a good OFF baseline, create a new ON transition, then return to OFF. Quality, IED timestamp, ARSAS timestamp, acquisition source and event order remain attached.

D

Stop and export

Seal the session, then export the Excel result copy, native PDF report or complete .arsas continuation project.

Optional continuation after complete discovery

When the discovery is complete and Diagnostics has no unresolved blocking error, the same IED context can produce a bounded engineering baseline.

B

C

Inspect the generated SCL, JSON evidence, Markdown summary and warnings before importing anything downstream.

D

Expected first outcome

One attributable live value—not a universal device approval.

A completed quick start proves that the selected endpoint, association and read path produced the displayed evidence at that time. It does not prove every service, every Logical Device, protection performance, time synchronization or IEC 61850 conformity.

When the path stops

Use the symptom library before changing the IED.

Start with port 102, model discovery, reporting, RCB ownership, file service, GOOSE sequence, IO FAT continuity or SCL evidence. Preserve negative results and the exact ARSAS version in an issue report.
