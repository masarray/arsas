IP-to-SCL workflow

Do not let a missing or rejected vendor file stop the integration.

The live server model can provide a typed engineering baseline when the available CID or ICD is missing, outdated, oversized for the receiving system, or rejected because identity, edition, DataSet or RCB expectations do not align.

01

Add the approved IED IP address

Confirm the intended physical device, routing and TCP port 102 inside the authorized laboratory or commissioning boundary.

02

Complete full live discovery

Read the physical identity, Logical Devices, Logical Nodes, Data Objects, Data Attributes, DataSets, Report Control Blocks and available type information.

03

Preserve the complete typed model

The operator signal list may stay compact, but the full discovery document remains attached for diagnostics and SCL generation.

04

Choose the target edition

Generate Edition 2 as IID or Edition 1 as ICD through schema-aware engine profiles.

05

Review evidence before import

Inspect the SCL, JSON evidence, Markdown summary and export findings, then validate the file in the receiving SAS or gateway.

Designed to preserve

Identity and relationships that importers depend on.

  • Physical IED identity separate from full MMS domain names
  • Typed LD, LN, DO and DA hierarchy
  • DataSet membership and ordering
  • Exact concrete runtime RCB names
  • Available trigger, optional-field and timing evidence
  • Endpoint, source and export provenance
Designed to reduce

Common multi-vendor import failures.

  • Logical Device names used as physical IED identity
  • Valid domains shortened or rewritten
  • Duplicate indexed RCB suffixes
  • Incomplete FCDA membership presented as complete
  • Edition 1 and Edition 2 expectations mixed silently
  • Unbounded project files passed to a limited importer
Opened-SCL conversion

Use configured intent without treating the source file as unquestioned truth.

ARSAS opens common SCL inputs, extracts endpoint and model context, preserves the original source, compares it with live evidence where available and can create bounded generic single-IED output with structured interoperability findings.

Bounded selected-RCB output

Prepare one intended reporting path for legacy SAS or gateway integration.

Run a read-only live availability audit, choose exactly one usable RCB, retain its verified DataSet members and available configuration evidence, and export an Edition 1 or Edition 2 CID baseline.

Engineering value

Reduce avoidable cleanup before FAT or SAT.

  • Start from live device evidence when a vendor file is unusable
  • Create a bounded output for the receiving system
  • Preserve exact identities and references
  • Keep warnings and provenance beside the output
  • Retain original source and discovery snapshots
Truthful boundary

Schema-aware output is not universal importer certification.

The receiving SAS, gateway or engineering tool may apply proprietary rules beyond the standard. Validate identity, communication, DataSets, RCBs, references and edition behavior under the approved project procedure.
