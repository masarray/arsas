Workflow IP-to-SCL

Jangan biarkan file vendor yang hilang atau ditolak menghentikan integrasi.

Live server model dapat menjadi typed engineering baseline saat CID/ICD yang tersedia hilang, outdated, terlalu besar untuk receiving system, atau ditolak karena identity, edition, DataSet maupun RCB tidak sesuai expectation.

01

Tambahkan alamat IP IED yang disetujui

Konfirmasi physical device, routing dan TCP port 102 dalam boundary laboratorium atau commissioning yang berwenang.

02

Selesaikan full live discovery

Baca physical identity, Logical Device, Logical Node, Data Object, Data Attribute, DataSet, Report Control Block dan type information yang tersedia.

03

Pertahankan complete typed model

Operator signal list dapat tetap ringkas, tetapi full discovery document tetap melekat untuk diagnostic dan generate SCL.

04

Pilih target edition

Generate Edition 2 sebagai IID atau Edition 1 sebagai ICD melalui schema-aware engine profile.

05

Review evidence sebelum import

Periksa SCL, JSON evidence, Markdown summary dan export findings, kemudian validasi file pada SAS atau gateway penerima.

Dirancang untuk mempertahankan

Identity dan relationship yang dibutuhkan importer.

  • Physical IED identity terpisah dari full MMS domain
  • Typed hierarchy LD, LN, DO dan DA
  • DataSet membership serta ordering
  • Exact concrete runtime RCB name
  • Trigger, optional-field dan timing evidence yang tersedia
  • Endpoint, source dan export provenance
Dirancang untuk mengurangi

Failure import multi-vendor yang umum.

  • Logical Device name dipakai sebagai physical IED identity
  • Valid domain dipotong atau ditulis ulang
  • Duplicate indexed RCB suffix
  • FCDA membership tidak lengkap dianggap complete
  • Expectation Edition 1 dan Edition 2 tercampur diam-diam
  • Project file besar dikirim ke importer yang terbatas
Konversi opened SCL

Gunakan configured intent tanpa menganggap source file selalu benar.

ARSAS membuka input SCL umum, mengambil endpoint dan model context, mempertahankan source asli, membandingkannya dengan live evidence jika tersedia, dan dapat menghasilkan bounded generic single-IED output dengan structured interoperability findings.

Bounded selected-RCB output

Siapkan satu reporting path untuk legacy SAS atau integrasi gateway.

Jalankan read-only live availability audit, pilih tepat satu RCB yang usable, pertahankan verified DataSet member serta configuration evidence, lalu export baseline CID Edition 1 atau Edition 2.

Nilai engineering

Kurangi cleanup yang dapat dihindari sebelum FAT atau SAT.

  • Mulai dari live device evidence saat vendor file tidak usable
  • Buat bounded output untuk receiving system
  • Pertahankan exact identity dan reference
  • Simpan warning dan provenance bersama output
  • Pertahankan source asli serta discovery snapshot
Batas yang jujur

Schema-aware output bukan sertifikasi universal importer.

SAS, gateway atau engineering tool penerima dapat menerapkan proprietary rule di luar standard. Validasi identity, communication, DataSet, RCB, reference dan edition behavior dalam procedure proyek yang disetujui.
