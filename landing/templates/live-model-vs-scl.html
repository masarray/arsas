Home / Guides / Live model vs SCL
Configured intent · running model · drift · recovery

The SCL file and the live relay answer different but complementary questions.

SCL describes configured engineering intent. Complete live MMS discovery shows what the connected IED currently exposes. ARSAS keeps both visible and provides a bounded recovery path when the source file is stale, incomplete or rejected by the receiving system.

SCL context

What was engineered or exported

  • IED and AccessPoint definitions
  • communication addressing
  • Logical Device and DataType templates
  • DataSets, RCBs and GOOSE intent
  • vendor-private engineering context
  • project revision and intended target
Live model

What the server exposes now

  • physical device identity and reachable endpoint
  • complete Logical Device, Node, object and attribute hierarchy
  • current DataSet and RCB inventory
  • live values, quality and timestamp evidence
  • supported service and access outcomes
  • available type and control-model evidence
Diagnostic path

Compare the relationships that affect the failed workflow.

A full-file textual difference can create noise. Focus on physical identity, endpoint, full domain names, object references, DataSet membership, RCB association, GOOSE identity or control model related to the observed problem.

01

Identify the controlled project source

Record filename, owner, revision, intended target and receiving-system expectation before comparing it with live evidence.

02

Discover the complete running model

Use the approved endpoint and retain physical identity, full MMS hierarchy, DataSets, RCBs, types and association context.

03

Compare functional references

Check the exact object, DataSet, RCB, GOOSE or communication reference required by the failed test.

04

Choose repair, normalization or regeneration

Repair the controlled source when it remains authoritative, normalize it into bounded single-IED output, or generate IID/ICD from complete live discovery when the source cannot be trusted.

05

Validate through the receiving engineering process

Import the bounded result and preserve exact acceptance or rejection evidence before updating the controlled baseline.

Use live generation when

The device is a stronger source than the available file.

  • the vendor CID or ICD is missing
  • the file describes an older firmware or configuration
  • physical identity and MMS domains do not align
  • DataSet or RCB inventory is incomplete
  • another tool rejects the file before useful comparison
Use configured SCL when

The project intent includes information MMS cannot reconstruct.

  • station communication design and subscribed relationships
  • project-wide GOOSE or Sampled Values intent
  • vendor-private engineering information
  • approved project naming and ownership decisions
  • configuration that has not yet been deployed to the IED
Continue with the actual failure mode

Choose the recovery path instead of editing XML blindly.

Use the CID rejection guide for importer errors, Smart Reporting for report mismatch, or the IP-to-SCL workspace for generation and bounded conversion.
